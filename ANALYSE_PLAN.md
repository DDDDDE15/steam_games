
## 1. Формулировка целей и гипотез

**Главная цель:** выявить закономерности успеха игр в Steam на основе метрик (оценки, количество игроков, владельцы, пики онлайна).

**Примерные гипотезы для проверки:**
- Бесплатные игры имеют низкие оценки, но огромную аудиторию.
- Высокая скидка (%) не всегда коррелирует с ростом оценок.
- Жанры «Action», «RPG», «Indie» доминируют по количеству игроков.
- Чем выше цена, тем выше ожидания → оценки могут быть ниже.
- Игры с мультиплеером имеют более высокий 24h_Peak_Players.
- Релизы 2025–2026 годов имеют мало отзывов → нужно фильтровать.
**Для каждой гипотезы указать статистический тест и порог значимости (p < 0.05)**
---

## 2. Предобработка данных (EDA + Cleaning)

- Пропуски: `Discount_Pct`, `Review_Score_Pct`, `Estimated_Owners`, `24h_Peak_Players`
- Выбросы: экстремальные значения `Total_Reviews` (CS2, Dota 2)
- Типы данных: даты → datetime, цену → float, скидку → int
- Создать новые признаки. Например:
  - `Actual_Price = Price_USD * (1 - Discount_Pct/100)`
  - `Release_Year / Release_Month`
  - `Is_Free = (Price_USD == 0)`
  - `Has_Discount = (Discount_Pct > 0)`
  - `Is_Upcoming = Release_Date > today`
  - `Reviews_Per_Owner = Total_Reviews / Estimated_Owners`
  - `Peak_To_Owners = 24h_Peak_Players / Estimated_Owners`

## 5. Дополнительные аналитические блоки

### A. Сегментация игр
Кластеризация (KMeans) по:
- цена
- оценка
- количество отзывов
- пиковый онлайн

→ выделить типы: «блокбастеры», «инди-хиты», «нишевые», «провальные», «бесплатные условно-успешные»

### B. "Скрытые жемчужины"
Игры с:
- `Review_Score_Pct > 90`
- `Total_Reviews < 5000`
- `Estimated_Owners < 200000`
- не от крупных издательств (можно определить по названию вручную частично)

### C. Падение интереса после пика
Для топ-20 игр по `24h_Peak_Players` посчитать отношение:
`24h_Peak_Players / Estimated_Owners * 100`
→ кто сохраняет аудиторию лучше всего

### D. Анализ тегов (NLP)
- Собрать все `All_Tags` в один корпус
- Частотный анализ
- Облако слов
- Поиск тегов, характерных для высокооценённых игр

### E. Факторы успеха (логистическая регрессия / дерево)
Целевая переменная: `is_success = (Review_Score_Pct > 85)`
Признаки: цена, бесплатность, скидка, количество тегов, год релиза, онлайн (log), жанр

* Можно попробовать ввывести:Success_Score = (Review_Score_Pct * 0.6) + (log(Estimated_Owners) * 0.4)
Или разделить на:
* Коммерческий успех → владельцы 
* Качественный успех → оценки

## 6. Возможные ограничения (не забыть указать)

- `Estimated_Owners` и `24h_Peak_Players` — приблизительные (особенно для старых/новых игр)
- Нет данных о регионе игроков, времени в игре, возвратах
- Много строчек с нулевыми значениями (нераспроданные новинки)
- `Steam_Deck_Status` везде Unknown — бесполезен на данный момент
